# PhotoPrint Service

Сервис фотопечати на Netlify: публичные страницы, форма заявки и панель управления. Дизайн и EJS-шаблоны сохранены, Express обслуживается через Netlify Functions без постоянно работающего сервера.

## Размещение на Netlify

Настройки находятся в `netlify.toml`. Каталог `public` публикуется как статика; остальные страницы и API обслуживает `netlify/functions/site.mts`. Отдельная команда сборки не требуется. EJS-шаблоны включены в серверную функцию.

Структурированные данные сохраняются в Netlify Database (Postgres) через `@netlify/database` и Drizzle ORM. Схема находится в `db/schema.ts`, миграции — в `netlify/database/migrations`. Netlify применяет миграции при публикации. Первая миграция создаёт таблицы и добавляет исходные настройки, пять услуг и четыре демонстрационных элемента галереи. Учётные записи администратора не создаются с паролем по умолчанию.

Изображения и видео сохраняются в Netlify Blobs и доступны по адресам `/uploads/services/...` и `/uploads/gallery/...`. Файлы сохраняются между вызовами функций и повторными публикациями. Максимальный размер одного файла — **4 МБ**, с учётом лимита HTTP-запроса Netlify Functions. Для услуг разрешены JPG, PNG и WEBP, для галереи также MP4.

## Вход администратора

Netlify Identity включается при публикации через маркер `.netlify/features/netlify-identity`.

1. В настройках проекта Netlify откройте Identity и рекомендуется ограничить регистрацию приглашениями.
2. Пригласите администратора по email и назначьте ему роль `admin` в серверных метаданных Identity.
3. Откройте ссылку из приглашения и задайте пароль. Сайт обрабатывает приглашение на странице входа.
4. Входите через `/admin/login`, используя email и пароль Netlify Identity.

Любой пользователь без роли `admin` не получает доступ к панели управления, заявкам и изменению содержимого. Прежние локальные JWT, пользователи SQLite и переменные `SESSION_SECRET`, `JWT_SECRET`, `ADMIN_PASSWORD` больше не используются. Уведомления после перенаправления передаются короткоживущими cookie, без серверных сессий в памяти. Ограничения частоты запросов хранятся в Postgres и действуют между экземплярами функций.

## Локальная проверка

```bash
npm install
netlify dev --port 8889
```

В отдельном терминале примените миграции к локальной базе:

```bash
netlify database migrations apply
```

Сайт доступен на `http://localhost:8889`. Для полного поведения Identity и Blobs используйте именно Netlify Dev, а не только `npm start`. Netlify Dev предоставляет локальную базу; если в окружении задан `NETLIFY_DB_URL`, он имеет приоритет. Не используйте production-базу для локальных тестов. Локальная авторизация требует включённого Identity на связанном сайте.

После изменения схемы создайте новую миграцию:

```bash
npm run db:generate -- --name describe_schema_change
```

`npm run seed` повторно добавляет отсутствующие исходные данные, не создавая администраторов и не сбрасывая существующие настройки. При первом размещении этот скрипт запускать не требуется.

## Дополнительные настройки

`BASE_URL` — необязательный адрес сайта для sitemap; без него используется адрес текущего сайта Netlify. Для почтовых уведомлений задайте `MAIL_HOST`, `MAIL_PORT`, `MAIL_USER`, `MAIL_PASS` и `MAIL_TO` в окружении Functions. Без SMTP заявка всё равно сохраняется, почтовое уведомление пропускается.

Исходные SQLite-данные и файлы из локального `public/uploads` не были включены в репозиторий. При наличии реальных данных на прежнем сервере их требуется перенести отдельно; они не восстанавливаются из демонстрационной миграции.

Если публичный адрес отвечает HTTP 401 с перенаправлением Netlify Edge Access, проверьте ограничения доступа к публикации в настройках Netlify. Эта защита работает до вызова приложения и не снимается изменением Express.
